# 悦途旅行预订 · 前端单页 + Java 后端

一个可跑起来的在线旅行预订演示项目：酒店 / 门票·活动 / 火车票 / 机票 / 汽车·船票 / 度假线路的搜索与下单，
配一个 Spring Boot + MySQL 的真实后端。**没有前端也能读完后端**：所有业务规则都落在服务端，页面只是其中一种调用方式。

```
悦途旅行预订.html          前端单文件应用（Vue 2.6.14，约 10000 行含模板与脚本），双击即可运行
ctrip-backend/             后端（Spring Boot 3.2.5 + Java 21 + MySQL 8）
  ├─ src/main/java/com/ctrip/
  │    controller/          HTTP 层：产品搜索、账号与五种登录、三种注册、订单、企业商旅、客服问答、状态页、扫码确认页与模拟授权页
  │    service/             业务层：计价与库存、订单状态机、会话与口令、短信/邮箱验证码、扫码场景、第三方绑定、定时清理
  │    config/              跨域策略 + 登录态拦截器
  │    api/                 统一响应体 {code,msg,data}
  ├─ sql/                   init.sql 建库建表 + 增量迁移脚本
  ├─ qa/smoke.sh            零依赖冒烟回归脚本
  └─ run-backend.bat        一键启动
```

## 1. 启动

前提：JDK 21、MySQL 8（本机 3306）、Maven 及其**离线仓库** `D:\Maven\m2repo`。
本项目全程用离线仓库构建，不联网下载依赖，命令里必须带上 `-Dmaven.repo.local`：

```bat
:: 1) 建库导数据（首次或想重置时）
ctrip-backend\init-db.bat

:: 2) 启动后端（端口 8080）
ctrip-backend\run-backend.bat
:: 等价命令：
cd ctrip-backend
D:\Maven\apache-maven-3.9.9\bin\mvn.cmd -o -Dmaven.repo.local=D:\Maven\m2repo spring-boot:run

:: 3) 打开前端
:: 直接双击「悦途旅行预订.html」即可；页面会请求 http://localhost:8080/api/**
```

自检：浏览器访问 <http://localhost:8080/> 会看到状态页，列出数据库实时统计与接口清单；
`http://localhost:8080/api/hotels?city=北京` 返回 JSON 即说明库通了。

前端的行为分三种，页面顶部会显示当前是哪种：

- **后端可用**：搜索、下单、库存、订单全部走 MySQL，刷新页面数据仍在。
- **后端不可用**：自动降级为本地演示数据（随机生成班次、订单存 `localStorage`），页面照常能走完流程。
- **混合**：特色体验活动、国际/港澳台航班这两类只有前端有数据，即使连着后端也在本地成单（MySQL 里没有对应商品记录）。

## 2. 接口与鉴权

| 接口 | 说明 | 需要登录 |
|---|---|---|
| `GET /api/hotels`、`/attractions`、`/trains`、`/flights`、`/buses`、`/ships`、`/vacations`、`/cars`、`/shop`、`/giftcards` | 商品搜索 | 否 |
| `POST /api/auth/register` | 注册：带 `email` 走邮箱注册，带 `code` 走手机号注册；两者都不给就是过去那种用户名+密码注册，直接拒（见 2.2） | 否 |
| `POST /api/auth/login` / `logout`、`GET /api/auth/me`、`POST /api/auth/password` | 账号密码登录（**用户名或注册邮箱都能填**）、退出、查身份、改密 | 改密需登录 |
| `POST /api/auth/sms/send` + `/sms/login` | 手机验证码登录的发码与校验 | 否 |
| `POST /api/auth/sms/register-code` | 手机号注册的发码（与登录码是两个场景，规则相反） | 否 |
| `POST /api/auth/email/send` + `/email/login` | 邮箱验证码登录的发码与校验 | 否 |
| `POST /api/auth/email/register-code` | 邮箱注册的发码（与登录码**共用同一地址的冷却与每小时配额**） | 否 |
| `POST /api/auth/oauth` | 发起一次第三方授权，渠道只认服务端 `OAuthService` 注册表里的 `wechat` / `qq` / `weibo` / `alipay` / `baidu`；返回 `state` 与授权页地址。登录与注册走同一条 | 否 |
| `GET /api/auth/oauth/{state}` | **只有发起页**轮询它：`APPROVED` 的那一次当场建号或登录并返回会话，令牌只送达一次 | 否 |
| `POST /api/auth/oauth/{state}/approve`、`/reject` | 授权页代表「渠道那边的人」同意或拒绝；身份只能从服务端内置的演示账号里挑 | 否（靠 state 本身） |
| `GET /oauth/authorize?state=` | 模拟授权页，服务端直出、不引外部资源、**绝不轮询** | 页面本身公开 |
| `POST /api/auth/qrcode`、`GET /api/auth/qrcode/{scene}` | 电脑创建扫码场景、轮询状态（`CONFIRMED` 时那一次返回带令牌） | 否 |
| `POST /api/auth/qrcode/{scene}/scan\|confirm\|reject` | 手机确认页代表**已登录的那台设备**上报扫码结果 | 是（自行校验） |
| `GET /scan?scene=` | 手机扫码后的确认页，服务端直出、不引外部资源 | 页面本身公开，操作要登录 |
| `POST /api/support/chat` | 7×24 客服问答（规则演示版） | 否 |
| `POST /api/orders` | 下单，生成**待支付**订单并锁定库存 | 是 |
| `GET /api/orders` | 本人订单列表（四种状态都返回） | 是 |
| `POST /api/orders/{orderNo}/pay` | 支付 | 是 |
| `POST /api/orders/{orderNo}/cancel` | 取消待支付订单 | 是 |
| `POST /api/orders/{orderNo}/refund` | 退款（已支付 → 已退款） | 是 |
| `DELETE /api/orders/{orderNo}` | 删除已取消 / 已退款的订单记录 | 是 |
| `DELETE /api/orders?confirm=YES` | 批量取消本人全部待支付订单 | 是 |
| `POST /api/biztravel` | 企业商旅提交 | 是 |
| `GET /api/biztravel?company=` | 企业商旅状态查询（无个人信息） | 否 |

**令牌读取优先级**：`Authorization: Bearer <token>` > `X-Token` > 查询参数 `?token=`。
查询参数只为兼容旧页面保留，它会进入访问日志与浏览器历史，前端已改为走 Header。

**受保护范围**由 `AuthInterceptor` 统一拦截 `/api/orders/**` 与 `/api/biztravel`（后者按 HTTP 方法放行 GET）。
拦截器挡下时返回 HTTP 401 + `{"code":401,...}`；`/api/auth/me` 不在拦截清单内，它自己判定会话，
未登录时返回 HTTP 200 + `{"code":1,"msg":"登录已过期，请重新登录"}`，前端据 `code` 清理登录态。

**登录门禁在「提交订单」这一步生效**：未登录点「提交预订」会弹出登录面板，预订表单里已填的内容不丢，
登录成功后自动补齐联系人并回到原弹窗。企业商旅提交同样如此。
降级成本地演示模式（后端不可用）也一样要先登录，本地账号存在 `localStorage` 里。

### 2.1 五种登录方式

登录是**一个面板、按方式换视图**（不再有「登录 / 注册 / 忘记密码」那条页签，标题就是当前方式名）：
默认展**账号密码**，底下「验证码登录」跳手机验证码、「免费注册」跳注册面板，邮箱验证码在下面的小链接行里，
**扫码登录**挂在卡片右缘的竖排标签上（二维码要占一块位置，收出去最紧凑），最下面一排**第三方圆标**。
五条路签出来的令牌完全同构（都是 `user_session` 表里的一行，都带签发时的 `auth_ver`），
所以订单等后续接口的鉴权口径不需要区分登录方式。

主按钮之前还有一道**协议门禁**：未勾选「阅读并同意服务协议与隐私政策」时，账号密码 / 两种验证码 / 第三方
五条提交入口一律先拦下（只弹提示、不自动代勾，勾上等于把门禁做成提示）。勾选状态记在
`localStorage.ctripAuthAgree`，只免掉每台浏览器每次都要点一下的繁琐，不构成法律上的同意、也不是后端凭据；
扫码不给「勾了才能看二维码」这条路，它自己的门禁是手机那台已登录设备。

- **账号密码**（默认视图）：`/login`，`username` 这一栏填服务端生成的用户名或**注册邮箱**都可以
  （输入先按邮箱格式判一次，格式合法就 `WHERE username = ? OR email = ?` 一起查）。
  连续失败 5 次锁定 15 分钟，用户不存在与密码错误给同一句提示；前端把在途请求占住（`pwdBusy`）避免连点敲阈值。
  注意「用户名+密码**注册**」这条通道已经下线（见 2.2），但**登录**这条留着——存量账号靠它进，
  密码框右侧的「忘记密码」跳到找回面板（验证码只能重置、不能找回）。
  后端不可达时降级成本地口令比对（`localPwdLogin`）：只拿本机存过的哈希比，**只登不建**，
  比的是简易哈希而非 PBKDF2，也没有失败锁定——所以后端一恢复就应当回到上一条路。
- **手机验证码**：`/sms/send` 发码 + `/sms/login` 校验。只有**已注册**的号码能登；一个号码挂着多个账号时
  （演示数据里 `13800138000` 就有三个）验证码只证明「这个号码是你的」，后端回 `needChoose` +
  一次性 `chooseToken` 与候选账号，由用户挑要登哪一个（二次提交不再重复消费验证码）——
  否则多归属的号码会把人堵在门外，而「拿别人号码随便挑一个账号登进去」也不能开。
  验证码 6 位、5 分钟有效、用一次即废、同一号码 60 秒内不能重发、每小时最多 5 条（**登录码与注册码合算**，
  换场景绕不过去），校验失败 5 次当场作废；库里只存 PBKDF2 哈希（6 位码只有 100 万种组合，存明文等于把 5 分钟窗口卖给能读库的人）。
- **邮箱验证码**：`/email/send` 发码 + `/email/login` 校验，规则与短信同构，只有两处不同——
  **有效期 10 分钟**（邮箱读得比短信慢，很多人一天只看两次），以及只有**已注册**的邮箱能登（不要求唯一，
  因为 `app_user.email` 本身就是 UNIQUE）。同一地址的登录码与注册码共用同一份 60 秒冷却与每小时 5 条配额。
- **扫码登录**：电脑 `POST /api/auth/qrcode` 拿到 `confirmUrl` 并渲染成二维码 →
  手机打开确认页（这台设备必须已登录）→ 点「确认登录」→ 电脑轮询到 `CONFIRMED`，
  **令牌在这一次请求里当场签发、且只送达一次**（领取用带状态条件的 `UPDATE` 原子认领，两个轮询同时到只有一个拿得到）。
  场景号是 32 位十六进制（`SecureRandom`），它本身就是这次登录的全部凭据，所以有效期只有 120 秒、单用一次，
  数据库里不存在「躺着等人来取」的会话。
  状态机：`PENDING → SCANNED → CONFIRMED →（领取即删除）`，另有 `REJECTED`（手机点取消，电脑不用干等）和 `EXPIRED`。
  认领条件里带着 `expire_time > NOW()`：**手机在有效期内确认了、电脑却过了期才来领，同样领不到令牌**，
  不会出现「两分钟的二维码，二十四小时内随时能换成一个新会话」。
  创建接口不要求登录，因此按 IP 限了每分钟上限（`qrcode-max-per-minute`），防止脚本把场景表刷满。
  确认页地址会自动把 `localhost` 换成本机局域网 IPv4——手机解不开「你这台机器」。
- **第三方授权**：与注册是同一条路（不另开接口），点底部圆标即 `POST /api/auth/oauth` 发起，
  首次授权当场建号并签会话，同一 `openId` 再授权就是登录——细见 2.2。
  发起之后的轮询起停只认 `syncAuthPanel()` 一个入口，并按 `oauthScope`（`login` / `register`）判归属：
  从登录圆标发起的场景，切去注册页签就该停轮询，关弹窗则整场作废。

### 2.2 三种注册方式（用户名不再由用户自取）

注册面板是三个子页签：**手机号注册 / 邮箱注册 / 第三方注册**。共同点是**都要先证明自己掌握了某个外部标识**，
通过后由服务端生成用户名并直接签发会话（省掉「注册完再登一次」）：
第三方那一个页签现在**只讲规则不摆按钮**——渠道圆标收在登录面板底部一排，登录与注册是同一条路。

- **手机号 + 验证码**：填手机号 → `/sms/register-code` 发码（注册场景与登录场景是 `sms_code.scene` 里两行，
  规则正好相反：注册只给**未注册**的号码发码）→ 用户名自动生成为 `m` + 手机号，昵称默认 `手机用户` + 尾号，
  密码留空时服务端给一个用户自己都不知道的随机口令（这个账号此后只能靠验证码登录）。
- **邮箱 + 验证码**：填邮箱 → `/email/register-code` 发码（只给**未注册**的邮箱发）→ `/register` 带 `email` + `code`
  建号。用户名取 `e` + 邮箱本地部分（`@` 与点号换成下划线、截到 24 字符，撞车就补随机后缀），昵称默认 `邮箱用户` + 前缀。
  这一步**可以**填一个自选密码（留空则同上给随机口令），填了就要过 8 位含字母数字的强度校验；
  注册成功后这个邮箱同时是登录账号，所以「忘了用户名」不成问题。
- **第三方（微信 / QQ / 微博 / 支付宝 / 百度）**：点渠道 → `POST /api/auth/oauth` 拿到 `state` 与授权页地址 →
  新窗口打开授权页、选一个演示身份同意 → 发起页轮询到 `APPROVED`，当场 `bindOrCreateByOAuth`：
  `user_oauth(provider, open_id)` 查到就登录，查不到就建号（用户名是 `wx_/qq_/wb_/ap_/bd_` + 8 位随机十六进制，
  口令是用户不知道的随机串，所以这个账号只能靠同一渠道再次授权登录）。
  靠 `UNIQUE(provider, open_id)` 保证同一个第三方身份只有一个账号；万一两个请求同瞬间给同一 `openId` 建号，
  后到的那个撞唯一键后会**删掉自己刚建的那行用户**、改读先赢的绑定。
  渠道清单只写一处：后端 `OAuthService.PROVIDERS` 那张注册表同时给 key、中文名、用户名前缀与品牌色，
  `UserService` 的前缀/渠道名与模拟授权页的主题色都从它读；前端 `oauthChannels` 那一排按钮与它一一对应，
  加一个渠道改这两处（不再是四处各写一遍）。

**「用户名 + 密码」注册为什么下线**：那条路径什么都不校验——不给邮箱、不给手机、不看验证码，
等于给批量建号开门，也是脚本刷库最容易的一条路。它下线后，`/register` 只认「带 `email`」或「带 `code`」两种载荷，
两者都不给就回一句指路三种方式的提示（冒烟脚本钉住了这句）。存量账号的**密码登录**不受影响。

所有昵称都写进 `app_user.nickname VARCHAR(50)`，超长按 50 字截断而不是抛异常
（早先直接插入会撞 MySQL 的 Data too long，用户看到的是一句 500）。

### 2.3 7×24 客服

右下角悬浮「悦途小助手」面板，走 `POST /api/support/chat`：**规则问答，不是大模型**，
页脚和每条回复上都标了「演示 · 规则问答」。命中关键词就回对应 FAQ 文案（顺序即优先级，「退款」排在「订单」前面，
「注册 / 第三方」排在「登录」前面，所以「微信登录怎么注册」答的是第三方注册而不是登录方式），
没命中给转人工话术与热线 400-168-6688。不要求登录（客服本来就该服务未登录访客），
消息截断到 500 字、单 IP 每分钟最多 30 条。后端不可达时前端回一句本地兜底话术，不假装是模型答案——
其中「本地模式不能新建账号」这句是必需的：用户名注册下线后，离线模式没有建号入口，只能登这台浏览器以前存过的账号。

## 3. 订单状态机与支付倒计时

```
            支付（15 分钟内）              退款
  待支付 ────────────────▶ 已支付 ────────────────▶ 已退款 ──┐
     │                                                      │
     │ 用户取消 / 超时自动取消                                │ 删除记录
     └────────────────────▶ 已取消 ◀─────────────────────────┘
```

- **下单只锁库存，不算付款**。库存（余票 / 余房）在 `ProductService.priceAndDeduct` 里计价并扣减，
  取消、退款、超时都通过 `ProductService.restoreStock` 原样回补——以前只有扣没有加，删一单库存就被永久磨掉。
- **支付窗口**：`ctrip.order.pay-deadline-minutes`（默认 15 分钟）。订单表存 `pay_deadline`，
  接口同时返回 `payExpireMs`（epoch 毫秒）与 `payDeadline`（可读串），前端倒计时读的就是它。
- **超时自动取消**两条路径：
  1. `OrderExpiryTask` 每 `ctrip.order.expiry-scan-ms`（默认 60 秒）扫一次
     `status='待支付' AND pay_deadline<=NOW()`，逐单取消并回补库存（单次最多 200 条）。
  2. 用户卡着最后一秒点「立即支付」时，`payOrder` 先就地取消再返回「支付超时，订单已自动取消，请重新下单」，
     倒计时因此没法被无限续期。
- **前端心跳**每 1 秒刷新一次剩余时间，归零时立刻把页面上的单子标为已取消（不必等后端下一轮扫描）；
  切回标签页时补一跳——浏览器会把后台页面的 `setInterval` 降频到每分钟一次，不补就会出现倒计时停在旧数字。
- **订单动作按钮**（去支付 / 取消订单 / 申请退款 / 删除）在订单中心的列表卡片和「订单详情」弹窗里各有一套，
  两处调用同一批方法、读同一组服务端标志 `payable` / `cancellable` / `refundable` / `deletable`，
  不会出现「列表能退、详情不能退」的口径分叉；
  按钮只由「归属 + 状态」推导，因此**同样状态的订单按钮必定相同**：无主历史单在 `listOrders` 里就被认领给当前账号，
  不再出现「列出来却一个按钮都按不动」的单子；这四个标志与 `serverOrder` 也**不写入 localStorage**
  （读回时一并剥掉陈旧值），否则缓存里的 `false` 会一直压着前端的状态兜底。
- **订单详情**：点列表里的订单号进入，展示规格、单价、实付、出行信息、联系人、手机号（后端已脱敏）、
  支付渠道，外加一条只列已发生事件的时间线（支付截止 → 支付 → 取消 → 退款）。
  **已支付订单可以在这页直接发起退款**，退款后页面不关闭，状态、时间线与「删除记录」按钮同步刷新。
  支付渠道不在 `travel_order` 表里（演示站没有真实扣款），由页面本地保存的订单附加信息补上。
- **幂等**：`idem_key`（前端沿用自己预生成的订单号）配合唯一索引 `uk_order_idem (idem_key, user_id)`。
  双击「提交订单」或网络重试只会有一笔真单、只扣一次库存。
  键的作用域限定到**人**：订单号是 `C+毫秒时间戳`，两个用户在同一毫秒下单不该被误判成重复提交。

## 4. 安全设计

| 主题 | 做法 |
|---|---|
| 口令存储 | PBKDF2-HMAC-SHA256，12 万次迭代，格式 `pbkdf2$迭代数$盐$哈希`；旧的 SHA-256 记录在登录成功时透明升级，历史账号不必强制改密 |
| 口令强度 | 至少 8 位且同时含字母与数字，注册、改密两处校验，前端先拦一道、后端为准 |
| 会话 | 令牌存 `user_session` 表（不是内存 Map），重启服务不掉登录态；`app_user.auth_ver` 每次改密递增，签发时记录的 `auth_ver` 一旦不等于当前值，该用户全部旧令牌同时失效 |
| 防爆破 | 同一「用户名@IP」连续失败 5 次锁定 15 分钟，**第 5 次失败当场就说明已锁定**；用户不存在与密码错误返回同一句提示，避免账号枚举 |
| 注册限流 | 同一 IP 每小时最多 `max-register-per-hour` 次注册尝试（**手机号与邮箱两条通道共用这一个窗口**）。第三方建号不走这个窗口：它必须先有一个服务端签发、两分钟有效、只能用一次的 `state`，而发起授权本身按 IP 限了 `oauth-max-per-minute` |
| 短信验证码 | 库里只存 PBKDF2 哈希；5 分钟有效、一次性（校验通过才把 `used=1`，且条件带上 `used=0` 并核对影响行数，两个请求同抢一码只有一个能成）、失败 5 次当场作废（同样置 `used=1`，不给无限重试）；同一号码 60 秒重发间隔 + 每小时 5 条**按号码合计、不分登录/注册场景**，另有单 IP 每小时总量兜住「换号码刷配额」。登录与注册是两个 `scene`，规则相反：登录要求号码已注册（多归属时先证归属、再由用户挑账号），注册只给未注册号码发码 |
| 扫码登录 | 场景号 32 位十六进制（`SecureRandom`）即本次登录的唯一凭据，120 秒有效、单用一次；令牌在电脑轮询到 `CONFIRMED` 的那一刻才签发，认领用带状态条件**且带 `expire_time > NOW()`** 的 `UPDATE` 原子完成——手机确认了但电脑过了期才来领，一样领不到令牌；被领走后同行删除，重复轮询只会看到「已失效」。未登录也能调的 `POST /api/auth/qrcode` 有 `qrcode-max-per-minute` 上限，兜住「脚本刷场景表」；手机侧 `scan/confirm/reject` 三个接口都要求这台设备已登录，且一个码只能被一台设备扫（`PENDING→SCANNED` 靠条件更新，抢输的一方直接提示重新发起） |
| 邮箱验证码 | 与短信同一套实现口径：库里只存 PBKDF2 哈希、10 分钟有效、一次性、失败 5 次作废、单地址 60 秒冷却 + 每小时 5 条（**登录码与注册码合算**）、单 IP 每小时总量兜底。多出来的一条约束是 `app_user.email` 带 UNIQUE，所以「一个邮箱挂多个账号」这种歧义在邮箱侧不存在 |
| 第三方登录与注册 | `state` 是 32 位十六进制 `SecureRandom`，与扫码场景号同一性质：它本身就是这条链路上唯一的凭据，120 秒有效、结果只能被发起页领取一次（带状态条件且带 `expire_time > NOW()` 的 `UPDATE` 原子认领，领完即删行）。授权页**只写不读**——它一旦读到状态就等于把令牌领走，所以页面里没有任何轮询；同意时只能从服务端内置的演示身份表里挑一个，**不接受调用方自报 `open_id`**，否则模拟页就变成「登录成任意账号」的后门。被拒绝 / 已过期的场景一律不签发会话，领取后回到授权页只剩一句无效链接提示（表单与脚本一起消失）。渠道清单只写一处：`OAuthService.PROVIDERS` 同时给 key、中文名、用户名前缀与品牌色，`UserService` 与模拟授权页都从它读（目前五个：微信 / QQ / 微博 / 支付宝 / 百度）|
| 客服问答 | 不接模型、不执行任何用户输入，回复是预置 FAQ 文案；消息截断 500 字、单 IP 每分钟 30 条，页面上标清「演示 · 规则问答」 |
| 前端登录态 | 扫码面板的每一次异步都带代际号 `qrSeq`，第三方面板另有一套 `oauthSeq`：关弹窗、切页签、连点「刷新二维码 / 重新发起授权」都会让上一轮的迟到响应作废，不会出现弹窗早关了二维码又活了、两个 interval 同时轮询、旧场景的 `EXPIRED` 停掉新轮询。起停只由 `syncAuthPanel()` 一个入口决定，第三方尤其不能「切到页签就自动发起」——一次发起就是一个新窗口，它也只由这个入口判归属：登录与注册共用同一个授权场景，`oauthScope`（`login` / `register`）记下这次是从哪个面板发起的，从登录圆标发起的场景切去注册页签就停轮询、关弹窗则整场作废。验证码的 60 秒重发窗口按后端返回的 `resendSeconds` 记成绝对时刻，关掉弹窗再回来仍按剩余时间续跑；后端回「请 N 秒后再获取」时前端就地锁回窗口内。手机码、邮箱登录码、手机注册码、邮箱注册码是**四条独立的倒计时通道**（`sms`/`email`/`reg`/`regEmail`），切页签不会互相把对方的秒数清零 |
| 归属隔离 | 订单写操作先校验 `user_id` 等于当前会话用户；不存在与没权限回同一句「订单不存在或不属于当前账号」，避免用错误码探测订单号 |
| 服务端计价 | 请求里的金额一律丢弃，单价与总价由服务端按商品表计算 |
| 个人信息 | 列表与详情接口回传的手机号统一掩码 `138****5678`；库里仍存明文（改签、退票、客服核对要用），但接口不再整表吐号 |
| 跨域 | 只放行 `http://localhost:*`、`http://127.0.0.1:*`；`file://` 打开页面的 `Origin: null` 由 `allow-file-origin` 单独控制；允许的头部显式列举，不用 `*` |
| 危险操作 | `DELETE /api/orders` 必须带 `?confirm=YES`，且语义已从「物理删除全部订单」改成「批量取消待支付并回补库存」 |
| SQL | 全部走 `JdbcTemplate` 参数绑定；状态页的统计表名是写死的白名单 |
| 页面注入 | 手机确认页、第三方模拟授权页与状态页都是服务端直出的静态模板：场景号 / `state` 先按 `[0-9a-f]{32}` 校验才拼进 HTML，非法值只回一句提示、不回显原值；拼进页面的昵称来自服务端内置表且用 `replace()` 字面替换（不是 `replaceAll`，含 `$1`、`\` 的昵称也不会炸模板）；页面不引任何外部资源 |
| 已知取舍 | 发码接口会区分「该手机号 / 该邮箱未注册」，等于给账号枚举留了一条路——这是「验证码只能登录已注册账号、注册只给未注册标识发码」这个选择的必然结果，兜底是标识与 IP 两级限流。更稳妥的做法（发码一律回「已发送」，存在性判断推迟到校验之后）本项目没做 |

口令不在仓库里：数据库账号密码取环境变量 `CTRIP_DB_USER` / `CTRIP_DB_PASSWORD`，
`application.yml` 里的默认值只为「clone 后能直接跑」。`.gitignore` 已排除 `.env`、`application-local.yml`、日志与构建产物。

没有单元测试框架——本地离线仓库里没有 junit / mockito / h2，也没有为测试联网下载它们。

**当前 216 条断言全绿、0 失败、0 跳过**（2026-10-28 在本机实跑，用的是下面第二条命令：给了 `MYSQL_BIN/MYSQL_PWD`
并把 `SMOKE_SWEEP=1` 打开，所以连「定时任务真的扫掉了超时订单」这一条也是跑过而不是跳过）。

重启后端清零内存计数再跑就恢复。

> 这些计数里有一批在内存，**重启后端就连同计数一起清零**——同小时内连跑到第三四次开始出现跳过时，重启比等一小时快。

### 6.1 浏览器端到端手测（脚本之外）

冒烟脚本走的是接口，页面这一层另外做了一轮真点按钮的复验（`file://` 打开、点页签与提交、用 DOM 断言读结果）：

- **邮箱注册**：明文码回显在弹窗里 → 点「注册并登录」直接登进来，服务端生成的用户名是 `ee2e_mail_1`、
  会话里带回了注册邮箱；「获取验证码」按钮当场变成 60 秒倒计时并禁用。
- **注册码与登录码共用冷却在前端的样子**：刚注册完就切到「邮箱验证码」页签要码，拿到的是后端那句
  「验证码已发送，请 60 秒后再获取」，并且这一页签的倒计时被锁到 59 秒——四条倒计时通道没有互相串秒数。
- **邮箱当账号做密码登录**：默认的 `账号密码` 视图里用户名那栏填邮箱 + 注册时设的密码，登进的是同一个 `id`。
- **登录面板版式与协议门禁**：标题随方式变（账号密码登录 / 手机验证码登录 / 邮箱验证码登录 / 扫码登录），
  通栏大输入框 + 橙色主按钮；未勾协议时四条提交入口都只弹提示不发包（把 `window.fetch` 换成计数探针断言调用次数为 0），
  勾上后才真发；「扫码登录」标签在卡片右缘，点它切视图、切回来轮询重新续上。
- **第三方授权**：从登录面板底部点「微信」后把 `window.open` 换成返回 null 以模拟拦弹窗，页面按预期降级成
  「浏览器拦截了新窗口」+ 一条可直接点的授权链接（不是默默转圈）；真实授权页在弹出的那个窗口里验过：
  三个演示身份、选中后点「同意并授权」变一句只读回执、按钮消失、倒计时继续显示剩余秒数。

> 截图这一项在本机做不了：这套自动化浏览器的视口报告为 0×0，`take_screenshot` 出来的图不可用。
> 布局类只能靠 DOM 结构与 computed style 断言，而且**computed style 也不全可信**——同一个 0×0 让
> CSS transition 的时钟停在 `currentTime: 0`，于是带 `transition: all .2s` 的元素在被读到的是
> **过渡起始值**（选中态的渠道按钮读到灰边灰字，而 `el.style.color` 明明是品牌色）；
> 读之前把 `transition` 置 `none`、或用 `getAnimations()` 确认没有卡住的过渡，才是真值。
> 要看像素就用无头 Edge：`msedge --headless --screenshot=出图 --window-size=宽,高 file:///对照页`。
> 要放进文档的界面截图，仍请用自己的浏览器手动截。

- **一个页面只做一个模块**。预订卡里原先那条「酒店 / 门票·活动 / 火车票 / 机票 / 汽车票 / 船票」六合一切换条
  已去掉（切模块只走左侧栏，它本来就覆盖全部模块），换成一条按模块驱动的卡头（computed `moduleHead`）：
  只说清「这是哪个模块的预订 + 要填哪些维度 + 本模块的承诺语」，如酒店 ＝ 「预订酒店 / 目的地 · 入住 · 离店 ·
  关键词 / 安心订 · 放心住」。同理，原先挂在酒店首页的「AI行程助手 / 世界旅游地图」两张卡也去掉了，
  `moduleQuickEntries` 现在只返回**本模块自己的**功能（火车＝时刻表 + 在线抢座，机票＝特价 + 航班动态，
  旅游＝签证 + 保险…）；酒店与门票没有本模块专属功能定义，就一张卡也不放，而不是借别的模块凑数。
  复验口径（无头 Edge 逐个点左侧栏）：`.search-tabs` 节点数为 0、可见的 `.search-form` 恰好 1 张且字段
  与该模块匹配、主列里不出现其他模块的搜索按钮字样。

## 8. 演示边界（重要的都在这）

这些不是隐藏的问题，而是这个项目刻意没有做的部分：

- **没有真实资金**。`/pay` 只是把状态从待支付改成已支付；退款同理，
  前端「申请退票」展示的 80% 退款比例是页面演示规则，后端只记状态与时间，不产生资金流水。
- **没有短信网关，也没有邮件服务**。手机 / 邮箱验证码都是服务端随机生成、**回显给页面**的
  （`expose-sms-code` / `expose-email-code`，关掉后明文只进后端日志），库里只存 PBKDF2 哈希；
  离线仓库里没有 `spring-boot-starter-mail`，所以「发信」这一步的实现就是 `EmailCodeService.deliver` 打一行日志。
  支付环节那道「短信验证码」仍是页面本地规则、固定 `888888`，两处都在界面上标了演示。别把支付那套当成登录的实现。
- **第三方注册是本站自演的一场授权**。真实项目里授权页在渠道方域名下（微信开放平台 / QQ 互联 / 微博开放平台），
  渠道登录后重定向回本站 callback，由**服务端**用 code 换 access_token、再换 openid；
  演示环境既没有渠道 appid/secret，也没有能对公网的 HTTPS 回调地址，所以由 `OauthConsentController` 直出一张扮演渠道的页面，
  页面上那几个身份（阿晨在旅行、Momo…）是内置演示数据、**不代表真实的人**，`open_id` 也不下发到页面。
  接真渠道时删掉这个类、改成一个 callback 处理器，其余状态机与 `user_oauth` 绑定逻辑不动。
- **7×24 客服是规则问答，不是模型**。回复来自 `SupportController` 里的关键词 → FAQ 模板表，
  没命中就转人工话术。接真实模型时替换 `answer()` 一个方法即可，出入参结构不变。
- **扫码登录与第三方授权要真机演示得满足两个条件**：手机和这台机器在同一个局域网（确认页与授权页地址都会把
  `localhost` 自动换成本机局域网 IPv4，拿不到就退回 localhost 并需要你配 `qrcode-confirm-base` / `oauth-authorize-base`），
  以及**上线必须整站 HTTPS**——
  HTTP 下二维码内容就是可被旁听的登录凭据，等同于把会话令牌贴在公告栏上；授权链接里的 `state` 同理。
- **本地演示模式（后端不可用）不能新建账号**：用户名+密码注册下线之后，离线模式没有任何「什么都不用验证就能建号」的入口，
  只能登这台浏览器以前存过的账号。这是刻意的取舍，不是漏做——注册页与客服面板都写了这句话。
- **AI 行程推荐是本地规则拼装的文案**，不是模型输出，页面上有标注。
- **特色体验活动 / 国际·港澳台航班 / 抢票 / 学生票 / 企业用车等**只在前端成单，MySQL 没有对应商品表。
- **限流与失败锁定计数在单机内存里**（`ConcurrentHashMap`），重启清零、多实例不共享。
  要真正防住分布式爆破需要落到数据库或 Redis，本项目规模下没做，代价写在这里。
- **数据库连接是明文口令 + `allowPublicKeyRetrieval=true`**，前提是「本机 MySQL、端口不出机器」。
  一旦 3306 暴露到局域网或公网，必须去掉这两项并改用 TLS。服务本身没有配 HTTPS。
- **加 `user_id` 之前那批无主历史订单**（`user_id IS NULL`）会在有人打开订单中心时被认领给当前账号
  （`listOrders` 开头一条 `UPDATE`）——既不「突然丢单」，也不会变成看得见改不了的只读摆件。
  代价是同浏览器上的多个账号里，谁先打开谁拿到这批老单；本来就没有归属信息可判，只能这样定一个。
- **前端是单文件、CDN 引入 Vue 2**，没有构建步骤，也因此没有组件级测试；
  改动后至少跑一遍 `qa/smoke.sh` 并双击页面走完一次下单-支付-取消。

## 9. 常见问题

**下单/搜索接口返回 400 或中文乱码。** Windows 的 curl 在命令行里传中文 JSON 会被 GBK 转码。
把请求体写成 UTF-8 文件再用 `--data-binary "@文件"` 发送（`qa/smoke.sh` 就是这么做的）。

**`mvn` 卡住或报找不到依赖。** 必须带 `-o -Dmaven.repo.local=D:\Maven\m2repo` 走离线仓库；
联网解析会去中央仓库下载，本机没有那个网络条件。

**8080 被占用。** `netstat -ano | findstr 8080` 找到 PID 后结束对应进程，
或改 `application.yml` 的 `server.port`（前端的接口地址写死在页面里，改端口要一并改前端）。

**登录提示「已临时锁定」。** 连续 5 次密码错误的后果，默认 15 分钟自动解开；
重启后端会连同计数一起清零。

**重复运行冒烟脚本被「注册过于频繁」挡住。** 同一 IP 每小时的注册尝试有上限（本地 `application.yml` 放宽到 30，生产口径 5）；
一次完整运行要注册 6 个账号，同小时连跑三次就会撞上。脚本遇限流报跳过而不是失败，
等一小时、或重启后端（连同内存计数一起清零）再跑。

**重跑脚本时扫码那一节整节跳过。** 是 `qrcode-max-per-minute`（默认 10）生效：
本节末尾会主动压满这个窗口来验证限流本身，所以同一分钟内紧接着再跑，预检就会被拒、整节改判跳过，等一分钟即可。

**收不到短信 / 邮箱验证码。** 本项目既没有短信网关也没有 SMTP：`expose-sms-code` / `expose-email-code` 为 `true` 时
码直接显示在弹窗里，设成 `false` 后只能去后端日志找那一行。演示站默认开着，对外部署必须关掉。
同一标识的重发冷却**登录码与注册码合并计算**（换场景绕不过去），所以刚用注册码建完号，
立刻切到登录页要同一个号码 / 同一个邮箱拿码，会先看到「请 60 秒后再获取」。

**冒烟脚本的邮箱登录那一节整节跳过。** 是 `email-max-per-hour-ip`（默认 20）生效：一次完整运行要发十几条邮箱码
（前置账号注册 + 邮箱注册各种反例 + 邮箱登录），同一小时内连跑两三次就把这个 IP 窗口用满，表现是发码返回「过于频繁」、
相关用例报**跳过**。它按整点划窗口（内存计数），所以要么等过下一个整点，要么重启后端清零。
单邮箱每小时只有 5 条，那一条更常撞到，报的是「该邮箱获取验证码过于频繁」。

**第三方注册点完渠道没反应 / 新窗口被拦。** 一次发起授权 = 一个新窗口，浏览器很容易拦掉，页面会显示
「浏览器拦截了新窗口」并给出可直接点的授权链接。真机/别的机器上打开要配 `oauth-authorize-base`。
授权页上只有内置的几个演示身份，选不到「你自己」的微信——那需要真实渠道 appid。

**注册时说「该邮箱已注册，请直接登录」。** 用户名注册下线后，邮箱就是账号标识之一，重复注册没有意义：
要么用那个邮箱走邮箱验证码登录，要么换一个邮箱。冒烟脚本的测试邮箱固定用 `@qa.smoke.test` 域，
脚本结尾会按这个域把账号、会话、验证码、绑定与订单一起清掉；手工留过数据的话按 §6 末尾的 SQL 清。

**手机扫不开二维码 / 扫开是空白页。** 确认页地址是 `http://<本机局域网IP>:8080/scan?scene=…`，
手机要和这台机器在同一个网络里，且 8080 未被防火墙挡住；只有一个回环网口的机器会退回 `localhost`，
那种情况请填 `ctrip.auth.qrcode-confirm-base`。二维码 2 分钟过期，点页面上的「刷新二维码」重新生成即可。

**页面上倒计时不动。** 浏览器对后台标签页的定时器降频所致，切回页面会立刻补上；
服务端的超时判定不依赖前端。同样的降频会影响扫码轮询与验证码重发倒计时，
所以页面在 `visibilitychange` 时补一次扫码查询、并按记录的绝对时刻重算剩余秒数。
