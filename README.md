# 悦途旅行预订 · 前端单页 + Java 后端

一个可跑起来的在线旅行预订演示项目：酒店 / 门票·活动 / 火车票 / 机票 / 汽车·船票 / 度假线路的搜索与下单，
配一个 Spring Boot + MySQL 的真实后端。**没有前端也能读完后端**：所有业务规则都落在服务端，页面只是其中一种调用方式。

```
悦途旅行预订.html          前端单文件应用（Vue 2.6.14，约 9500 行含模板与脚本），双击即可运行
ctrip-backend/             后端（Spring Boot 3.2.5 + Java 21 + MySQL 8）
  ├─ src/main/java/com/ctrip/
  │    controller/          HTTP 层：产品搜索、账号与三种登录、订单、企业商旅、客服问答、状态页与扫码确认页
  │    service/             业务层：计价与库存、订单状态机、会话与口令、验证码、扫码场景、定时清理
  │    config/              跨域策略 + 登录态拦截器
  │    api/                 统一响应体 {code,msg,data}
  ├─ sql/                   init.sql 建库建表 + 增量迁移脚本
  ├─ qa/smoke.sh            零依赖冒烟回归脚本
  └─ run-backend.bat        一键启动
```

## 1. 启动

前提：JDK 21、MySQL 8（本机 3306）、Maven 及其**离线仓库** `D:\Maven\m2repo`。
本项目全程用离线仓库构建，不联网下载依赖，命令里必须带上 `-Dmaven.repo.local`：

```bat
:: 1) 建库导数据（首次或想重置时）
ctrip-backend\init-db.bat

:: 2) 启动后端（端口 8080）
ctrip-backend\run-backend.bat
:: 等价命令：
cd ctrip-backend
D:\Maven\apache-maven-3.9.9\bin\mvn.cmd -o -Dmaven.repo.local=D:\Maven\m2repo spring-boot:run

:: 3) 打开前端
:: 直接双击「悦途旅行预订.html」即可；页面会请求 http://localhost:8080/api/**
```

自检：浏览器访问 <http://localhost:8080/> 会看到状态页，列出数据库实时统计与接口清单；
`http://localhost:8080/api/hotels?city=北京` 返回 JSON 即说明库通了。

前端的行为分三种，页面顶部会显示当前是哪种：

- **后端可用**：搜索、下单、库存、订单全部走 MySQL，刷新页面数据仍在。
- **后端不可用**：自动降级为本地演示数据（随机生成班次、订单存 `localStorage`），页面照常能走完流程。
- **混合**：特色体验活动、国际/港澳台航班这两类只有前端有数据，即使连着后端也在本地成单（MySQL 里没有对应商品记录）。

## 2. 接口与鉴权

| 接口 | 说明 | 需要登录 |
|---|---|---|
| `GET /api/hotels`、`/attractions`、`/trains`、`/flights`、`/buses`、`/ships`、`/vacations`、`/cars`、`/shop`、`/giftcards` | 商品搜索 | 否 |
| `POST /api/auth/register` | 注册：带 `code` 走手机号+验证码，不带则用户名+密码 | 否 |
| `POST /api/auth/login` / `logout`、`GET /api/auth/me`、`POST /api/auth/password` | 账号密码登录、退出、查身份、改密 | 改密需登录 |
| `POST /api/auth/sms/send` + `/sms/login` | 手机验证码登录的发码与校验 | 否 |
| `POST /api/auth/sms/register-code` | 手机号注册的发码（与登录码是两个场景，规则相反） | 否 |
| `POST /api/auth/qrcode`、`GET /api/auth/qrcode/{scene}` | 电脑创建扫码场景、轮询状态（`CONFIRMED` 时那一次返回带令牌） | 否 |
| `POST /api/auth/qrcode/{scene}/scan\|confirm\|reject` | 手机确认页代表**已登录的那台设备**上报扫码结果 | 是（自行校验） |
| `GET /scan?scene=` | 手机扫码后的确认页，服务端直出、不引外部资源 | 页面本身公开，操作要登录 |
| `POST /api/support/chat` | 7×24 客服问答（规则演示版） | 否 |
| `POST /api/orders` | 下单，生成**待支付**订单并锁定库存 | 是 |
| `GET /api/orders` | 本人订单列表（四种状态都返回） | 是 |
| `POST /api/orders/{orderNo}/pay` | 支付 | 是 |
| `POST /api/orders/{orderNo}/cancel` | 取消待支付订单 | 是 |
| `POST /api/orders/{orderNo}/refund` | 退款（已支付 → 已退款） | 是 |
| `DELETE /api/orders/{orderNo}` | 删除已取消 / 已退款的订单记录 | 是 |
| `DELETE /api/orders?confirm=YES` | 批量取消本人全部待支付订单 | 是 |
| `POST /api/biztravel` | 企业商旅提交 | 是 |
| `GET /api/biztravel?company=` | 企业商旅状态查询（无个人信息） | 否 |

**令牌读取优先级**：`Authorization: Bearer <token>` > `X-Token` > 查询参数 `?token=`。
查询参数只为兼容旧页面保留，它会进入访问日志与浏览器历史，前端已改为走 Header。

**受保护范围**由 `AuthInterceptor` 统一拦截 `/api/orders/**` 与 `/api/biztravel`（后者按 HTTP 方法放行 GET）。
拦截器挡下时返回 HTTP 401 + `{"code":401,...}`；`/api/auth/me` 不在拦截清单内，它自己判定会话，
未登录时返回 HTTP 200 + `{"code":1,"msg":"登录已过期，请重新登录"}`，前端据 `code` 清理登录态。

**登录门禁在「提交订单」这一步生效**：未登录点「提交预订」会弹出登录面板，预订表单里已填的内容不丢，
登录成功后自动补齐联系人并回到原弹窗。企业商旅提交同样如此。
降级成本地演示模式（后端不可用）也一样要先登录，本地账号存在 `localStorage` 里。

### 2.1 三种登录方式

登录面板里是三个子页签：**账号密码 / 手机验证码 / 扫码登录**。三条路签出来的令牌完全同构
（都是 `user_session` 表里的一行，都带签发时的 `auth_ver`），所以订单等后续接口的鉴权口径不需要区分登录方式。

- **账号密码**：`/login`。连续失败 5 次锁定 15 分钟，用户不存在与密码错误给同一句提示。
- **手机验证码**：`/sms/send` 发码 + `/sms/login` 校验。只有**已注册且唯一归属**的号码能登——
  一个号码挂着多个账号时（演示数据里 `13800138000` 就有三个）一律要求改用账号密码，
  否则验证码登录会变成「拿别人号码随便挑一个账号登进去」。
  验证码 6 位、5 分钟有效、用一次即废、同一号码 60 秒内不能重发、每小时最多 5 条（**登录码与注册码合算**，
  换场景绕不过去），校验失败 5 次当场作废；库里只存 PBKDF2 哈希（6 位码只有 100 万种组合，存明文等于把 5 分钟窗口卖给能读库的人）。
- **扫码登录**：电脑 `POST /api/auth/qrcode` 拿到 `confirmUrl` 并渲染成二维码 →
  手机打开确认页（这台设备必须已登录）→ 点「确认登录」→ 电脑轮询到 `CONFIRMED`，
  **令牌在这一次请求里当场签发、且只送达一次**（领取用带状态条件的 `UPDATE` 原子认领，两个轮询同时到只有一个拿得到）。
  场景号是 32 位十六进制（`SecureRandom`），它本身就是这次登录的全部凭据，所以有效期只有 120 秒、单用一次，
  数据库里不存在「躺着等人来取」的会话。
  状态机：`PENDING → SCANNED → CONFIRMED →（领取即删除）`，另有 `REJECTED`（手机点取消，电脑不用干等）和 `EXPIRED`。
  认领条件里带着 `expire_time > NOW()`：**手机在有效期内确认了、电脑却过了期才来领，同样领不到令牌**，
  不会出现「两分钟的二维码，二十四小时内随时能换成一个新会话」。
  创建接口不要求登录，因此按 IP 限了每分钟上限（`qrcode-max-per-minute`），防止脚本把场景表刷满。
  确认页地址会自动把 `localhost` 换成本机局域网 IPv4——手机解不开「你这台机器」。

### 2.2 两种注册方式

- **用户名 + 密码**：老路径，口令强度规则同下。
- **手机号 + 验证码**：填手机号 → `/sms/register-code` 发码（注册场景与登录场景是 `sms_code.scene` 里两行，
  规则正好相反：注册只给**未注册**的号码发码）→ 提交后服务端建号并**直接返回会话**，省掉「注册完再登一次」。
  用户名自动生成为 `m` + 手机号，昵称默认 `手机用户` + 尾号，
  昵称超过 50 字按 50 字截断（`app_user.nickname` 就是 VARCHAR(50)，早先直接插入会撞 MySQL 的 Data too long 变成 500），
  密码留空时服务端给一个用户自己都不知道的随机口令（这个账号此后只能靠验证码登录）。

### 2.3 7×24 客服

右下角悬浮「悦途小助手」面板，走 `POST /api/support/chat`：**规则问答，不是大模型**，
页脚和每条回复上都标了「演示 · 规则问答」。命中关键词就回对应 FAQ 文案（顺序即优先级，「退款」排在「订单」前面），
没命中给转人工话术与热线 400-168-6688。不要求登录（客服本来就该服务未登录访客），
消息截断到 500 字、单 IP 每分钟最多 30 条。后端不可达时前端回一句本地兜底话术，不假装是模型答案。

## 3. 订单状态机与支付倒计时

```
            支付（15 分钟内）              退款
  待支付 ────────────────▶ 已支付 ────────────────▶ 已退款 ──┐
     │                                                      │
     │ 用户取消 / 超时自动取消                                │ 删除记录
     └────────────────────▶ 已取消 ◀─────────────────────────┘
```

- **下单只锁库存，不算付款**。库存（余票 / 余房）在 `ProductService.priceAndDeduct` 里计价并扣减，
  取消、退款、超时都通过 `ProductService.restoreStock` 原样回补——以前只有扣没有加，删一单库存就被永久磨掉。
- **支付窗口**：`ctrip.order.pay-deadline-minutes`（默认 15 分钟）。订单表存 `pay_deadline`，
  接口同时返回 `payExpireMs`（epoch 毫秒）与 `payDeadline`（可读串），前端倒计时读的就是它。
- **超时自动取消**两条路径：
  1. `OrderExpiryTask` 每 `ctrip.order.expiry-scan-ms`（默认 60 秒）扫一次
     `status='待支付' AND pay_deadline<=NOW()`，逐单取消并回补库存（单次最多 200 条）。
  2. 用户卡着最后一秒点「立即支付」时，`payOrder` 先就地取消再返回「支付超时，订单已自动取消，请重新下单」，
     倒计时因此没法被无限续期。
- **前端心跳**每 1 秒刷新一次剩余时间，归零时立刻把页面上的单子标为已取消（不必等后端下一轮扫描）；
  切回标签页时补一跳——浏览器会把后台页面的 `setInterval` 降频到每分钟一次，不补就会出现倒计时停在旧数字。
- **订单动作按钮**（去支付 / 取消订单 / 申请退款 / 删除）在订单中心的列表卡片和「订单详情」弹窗里各有一套，
  两处调用同一批方法、读同一组服务端标志 `payable` / `cancellable` / `refundable` / `deletable`，
  不会出现「列表能退、详情不能退」的口径分叉；
  别人的订单、无主的历史订单（`user_id` 为空）四个标志都是 `false`，按钮直接不出现。
- **订单详情**：点列表里的订单号进入，展示规格、单价、实付、出行信息、联系人、手机号（后端已脱敏）、
  支付渠道，外加一条只列已发生事件的时间线（支付截止 → 支付 → 取消 → 退款）。
  **已支付订单可以在这页直接发起退款**，退款后页面不关闭，状态、时间线与「删除记录」按钮同步刷新。
  支付渠道不在 `travel_order` 表里（演示站没有真实扣款），由页面本地保存的订单附加信息补上。
- **幂等**：`idem_key`（前端沿用自己预生成的订单号）配合唯一索引 `uk_order_idem (idem_key, user_id)`。
  双击「提交订单」或网络重试只会有一笔真单、只扣一次库存。
  键的作用域限定到**人**：订单号是 `C+毫秒时间戳`，两个用户在同一毫秒下单不该被误判成重复提交。

## 4. 安全设计

| 主题 | 做法 |
|---|---|
| 口令存储 | PBKDF2-HMAC-SHA256，12 万次迭代，格式 `pbkdf2$迭代数$盐$哈希`；旧的 SHA-256 记录在登录成功时透明升级，历史账号不必强制改密 |
| 口令强度 | 至少 8 位且同时含字母与数字，注册、改密两处校验，前端先拦一道、后端为准 |
| 会话 | 令牌存 `user_session` 表（不是内存 Map），重启服务不掉登录态；`app_user.auth_ver` 每次改密递增，签发时记录的 `auth_ver` 一旦不等于当前值，该用户全部旧令牌同时失效 |
| 防爆破 | 同一「用户名@IP」连续失败 5 次锁定 15 分钟，**第 5 次失败当场就说明已锁定**；用户不存在与密码错误返回同一句提示，避免账号枚举 |
| 注册限流 | 同一 IP 每小时最多 `max-register-per-hour` 次注册尝试（两种注册方式共用这一个窗口） |
| 短信验证码 | 库里只存 PBKDF2 哈希；5 分钟有效、一次性（校验通过才把 `used=1`，且条件带上 `used=0` 并核对影响行数，两个请求同抢一码只有一个能成）、失败 5 次当场作废（同样置 `used=1`，不给无限重试）；同一号码 60 秒重发间隔 + 每小时 5 条**按号码合计、不分登录/注册场景**，另有单 IP 每小时总量兜住「换号码刷配额」。登录与注册是两个 `scene`，规则相反：登录要求号码唯一归属，注册只给未注册号码发码 |
| 扫码登录 | 场景号 32 位十六进制（`SecureRandom`）即本次登录的唯一凭据，120 秒有效、单用一次；令牌在电脑轮询到 `CONFIRMED` 的那一刻才签发，认领用带状态条件**且带 `expire_time > NOW()`** 的 `UPDATE` 原子完成——手机确认了但电脑过了期才来领，一样领不到令牌；被领走后同行删除，重复轮询只会看到「已失效」。未登录也能调的 `POST /api/auth/qrcode` 有 `qrcode-max-per-minute` 上限，兜住「脚本刷场景表」；手机侧 `scan/confirm/reject` 三个接口都要求这台设备已登录，且一个码只能被一台设备扫（`PENDING→SCANNED` 靠条件更新，抢输的一方直接提示重新发起） |
| 客服问答 | 不接模型、不执行任何用户输入，回复是预置 FAQ 文案；消息截断 500 字、单 IP 每分钟 30 条，页面上标清「演示 · 规则问答」 |
| 前端登录态 | 扫码面板的每一次异步都带代际号 `qrSeq`：关弹窗、切页签、连点「刷新二维码」都会让上一轮「创建场景 / 轮询」的迟到响应作废，不会出现弹窗早关了二维码又活了、两个 interval 同时轮询、旧场景的 `EXPIRED` 停掉新轮询。验证码的 60 秒重发窗口按后端返回的 `resendSeconds` 记成绝对时刻，关掉弹窗再回来仍按剩余时间续跑；后端回「请 N 秒后再获取」时前端就地锁回窗口内 |
| 归属隔离 | 订单写操作先校验 `user_id` 等于当前会话用户；不存在与没权限回同一句「订单不存在或不属于当前账号」，避免用错误码探测订单号 |
| 服务端计价 | 请求里的金额一律丢弃，单价与总价由服务端按商品表计算 |
| 个人信息 | 列表与详情接口回传的手机号统一掩码 `138****5678`；库里仍存明文（改签、退票、客服核对要用），但接口不再整表吐号 |
| 跨域 | 只放行 `http://localhost:*`、`http://127.0.0.1:*`；`file://` 打开页面的 `Origin: null` 由 `allow-file-origin` 单独控制；允许的头部显式列举，不用 `*` |
| 危险操作 | `DELETE /api/orders` 必须带 `?confirm=YES`，且语义已从「物理删除全部订单」改成「批量取消待支付并回补库存」 |
| SQL | 全部走 `JdbcTemplate` 参数绑定；状态页的统计表名是写死的白名单 |
| 页面注入 | 手机确认页与状态页都是服务端直出的静态模板：场景号先按 `[0-9a-f]{32}` 校验才拼进 HTML，非法值只回一句提示、不回显原值；页面不引任何外部资源 |
| 已知取舍 | 发码接口会区分「该手机号未注册」，等于给账号枚举留了一条路——这是「验证码只能登录已注册账号」这个选择的必然结果，兜底是号码与 IP 两级限流。更稳妥的做法（发码一律回「已发送」，存在性判断推迟到校验之后）本项目没做 |

口令不在仓库里：数据库账号密码取环境变量 `CTRIP_DB_USER` / `CTRIP_DB_PASSWORD`，
`application.yml` 里的默认值只为「clone 后能直接跑」。`.gitignore` 已排除 `.env`、`application-local.yml`、日志与构建产物。

## 5. 配置项

`ctrip-backend/src/main/resources/application.yml`：

```yaml
ctrip:
  cors:
    allowed-origins: http://localhost:*,http://127.0.0.1:*
    allow-file-origin: true          # 上线设 false，否则任何本地网页都能冒充页面来源
  auth:
    max-login-failures: 5            # 触发锁定的连续失败次数
    lock-minutes: 15                 # 锁定时长
    max-register-per-hour: 30        # 同一 IP 每小时注册尝试上限（生产口径 5；这里放宽只为连跑冒烟脚本）
    sms-code-ttl-seconds: 300        # 验证码有效期
    sms-resend-seconds: 60           # 同一号码重发间隔
    sms-max-per-hour: 5              # 同一号码每小时发码上限
    sms-max-per-hour-ip: 20          # 同一 IP 每小时发码上限（挡住换号码刷配额）
    sms-max-attempts: 5              # 一张码允许的校验失败次数，用满即作废
    expose-sms-code: true            # 演示站没有短信网关，开着才把明文码回显给页面；对外必须 false
    qrcode-ttl-seconds: 120          # 二维码场景有效期
    qrcode-max-per-minute: 10        # 未登录也能调的「创建二维码」每分钟上限（按 IP）
    qrcode-confirm-base: ""          # 留空按请求 Host 推断（localhost 会自动换局域网 IPv4）；
                                     # 真机演示可写死 http://192.168.1.23:8080/scan?scene=
  order:
    pay-deadline-minutes: 15         # 支付窗口，超时自动取消
    expiry-scan-ms: 60000            # 过期扫描间隔
```

前端本地演示模式的窗口在 `悦途旅行预订.html` 的 `localPayWindowMin`（同样 15 分钟），
两边不一致时用户看到的倒计时会和实际判定条件脱节。

## 6. 回归验证

没有单元测试框架——本地离线仓库里没有 junit / mockito / h2，也没有为测试联网下载它们。
替代方案是零依赖的冒烟脚本 `qa/smoke.sh`（curl + node），把上面这些行为逐条钉住，

（要等下一轮扫描、最长 90 秒，只有 `set SMOKE_SWEEP=1` 时才跑）。

```bat
:: 先启动后端，然后：
cd ctrip-backend
bash qa/smoke.sh

:: 想顺带验证「定时任务真的会扫掉超时订单」，再提供 MySQL 客户端：

```

幂等重复提交、归属隔离与越权、手机号掩码、**待支付 → 支付 → 退款 → 删除** 全链路、
**待支付 → 取消 → 删除**、支付超时（接口就地取消 + `OrderExpiryTask` 扫描两条路径）、
批量取消需显式确认且只动待支付、登录失败锁定、
**手机验证码**（发码 / 重发冷却 / 错码与过期同句提示 / 一次性 / 号码未注册与多归属两种拒绝）、
**手机号注册**（注册码与登录码规则相反、错码建不了号、成功后直接签发会话、昵称超长截到 50 字而不是 500）、

匿名扫码 401、非法场景号不出确认页、每分钟创建上限）、
**客服**（命中规则、转人工兜底、空消息被拒、演示来源标注）、CORS 三种来源。

结束时会自动清掉账号、会话、验证码、扫码场景与订单，

提供了 `MYSQL_BIN/MYSQL_PWD` 时会直接连库把支付截止时刻、二维码到期时间改到过去，几秒就能验完超时逻辑。

## 8. 演示边界（重要的都在这）

这些不是隐藏的问题，而是这个项目刻意没有做的部分：

- **没有真实资金**。`/pay` 只是把状态从待支付改成已支付；退款同理，
  前端「申请退票」展示的 80% 退款比例是页面演示规则，后端只记状态与时间，不产生资金流水。
- **没有短信网关**。登录 / 注册的验证码是服务端随机生成、**回显给页面**的（`ctrip.auth.expose-sms-code`，
  关掉后明文只进后端日志），库里只存 PBKDF2 哈希；支付环节那道「短信验证码」仍是页面本地规则、固定 `888888`，
  两处都在界面上标了演示。两者是不同的东西，别把支付那套当成登录的实现。
- **7×24 客服是规则问答，不是模型**。回复来自 `SupportController` 里的关键词 → FAQ 模板表，
  没命中就转人工话术。接真实模型时替换 `answer()` 一个方法即可，出入参结构不变。
- **扫码登录要真机演示得满足两个条件**：手机和这台机器在同一个局域网（确认页地址会自动把 `localhost` 换成局域网 IPv4，
  拿不到就退回 localhost 并需要你配 `qrcode-confirm-base`），以及**上线必须整站 HTTPS**——
  HTTP 下二维码内容就是可被旁听的登录凭据，等同于把会话令牌贴在公告栏上。
- **AI 行程推荐是本地规则拼装的文案**，不是模型输出，页面上有标注。
- **特色体验活动 / 国际·港澳台航班 / 抢票 / 学生票 / 企业用车等**只在前端成单，MySQL 没有对应商品表。
- **限流与失败锁定计数在单机内存里**（`ConcurrentHashMap`），重启清零、多实例不共享。
  要真正防住分布式爆破需要落到数据库或 Redis，本项目规模下没做，代价写在这里。
- **数据库连接是明文口令 + `allowPublicKeyRetrieval=true`**，前提是「本机 MySQL、端口不出机器」。
  一旦 3306 暴露到局域网或公网，必须去掉这两项并改用 TLS。服务本身没有配 HTTPS。
- **加 `user_id` 之前那批无主历史订单**（`user_id IS NULL`）对任何登录用户都可见——
  这是为了避免升级后「突然丢单」；代价是这些单子谁也看得见、谁也改不了（支付/取消/退款/删除四个动作标志恒为 `false`）。
  需要彻底断开可以在库里补一条 `UPDATE travel_order SET user_id = <某人> WHERE user_id IS NULL`。
- **前端是单文件、CDN 引入 Vue 2**，没有构建步骤，也因此没有组件级测试；
  改动后至少跑一遍 `qa/smoke.sh` 并双击页面走完一次下单-支付-取消。

## 9. 常见问题

**下单/搜索接口返回 400 或中文乱码。** Windows 的 curl 在命令行里传中文 JSON 会被 GBK 转码。
把请求体写成 UTF-8 文件再用 `--data-binary "@文件"` 发送（`qa/smoke.sh` 就是这么做的）。

**`mvn` 卡住或报找不到依赖。** 必须带 `-o -Dmaven.repo.local=D:\Maven\m2repo` 走离线仓库；
联网解析会去中央仓库下载，本机没有那个网络条件。

**8080 被占用。** `netstat -ano | findstr 8080` 找到 PID 后结束对应进程，
或改 `application.yml` 的 `server.port`（前端的接口地址写死在页面里，改端口要一并改前端）。

**登录提示「已临时锁定」。** 连续 5 次密码错误的后果，默认 15 分钟自动解开；
重启后端会连同计数一起清零。

**重复运行冒烟脚本被「注册过于频繁」挡住。** 同一 IP 每小时的注册尝试有上限（本地 `application.yml` 放宽到 30，生产口径 5）；
一次完整运行要注册 6 个账号，同小时连跑三次就会撞上。脚本遇限流报跳过而不是失败，
等一小时、或重启后端（连同内存计数一起清零）再跑。

**重跑脚本时扫码那一节整节跳过。** 是 `qrcode-max-per-minute`（默认 10）生效：
本节末尾会主动压满这个窗口来验证限流本身，所以同一分钟内紧接着再跑，预检就会被拒、整节改判跳过，等一分钟即可。

**收不到短信验证码。** 本项目没有短信网关：`expose-sms-code: true` 时码直接显示在弹窗里，
设成 `false` 后只能去后端日志找那一行。演示站默认开着，对外部署必须关掉。
同一号码的重发冷却**登录码与注册码合并计算**（换场景绕不过去），所以刚用注册码建完号，
立刻切到登录页要同一个号码拿码，会先看到「请 60 秒后再获取」。

**手机扫不开二维码 / 扫开是空白页。** 确认页地址是 `http://<本机局域网IP>:8080/scan?scene=…`，
手机要和这台机器在同一个网络里，且 8080 未被防火墙挡住；只有一个回环网口的机器会退回 `localhost`，
那种情况请填 `ctrip.auth.qrcode-confirm-base`。二维码 2 分钟过期，点页面上的「刷新二维码」重新生成即可。

**页面上倒计时不动。** 浏览器对后台标签页的定时器降频所致，切回页面会立刻补上；
服务端的超时判定不依赖前端。同样的降频会影响扫码轮询与验证码重发倒计时，
所以页面在 `visibilitychange` 时补一次扫码查询、并按记录的绝对时刻重算剩余秒数。
